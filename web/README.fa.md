# نسخهٔ وب تمرینی — اجرا با Nodemon، بدون Docker

پیش‌نیاز: **Node.js 24** و **MongoDB Community Server**. برنامهٔ MongoDB Compass فقط ابزار مشاهدهٔ دیتابیس است؛ فایل `mongod.exe` از نصب MongoDB Server نیز باید موجود باشد. هاست و دامنه لازم نیست.

## شروع سریع

داخل همین پوشه که `package.json` قرار دارد، ترمینال را باز کنید:

```sh
npm ci
npm run dev
```

در ویندوز می‌توانید به‌جای تایپ دستورها روی `start-web.cmd` دوبار کلیک کنید؛ این فایل دیگر Docker را اجرا نمی‌کند.

در اولین اجرا، `.env` ساخته و **کد راه‌اندازی مدیر** در ترمینال نمایش داده می‌شود. سپس آدرس `http://127.0.0.1:3000` را باز کنید، کد را وارد و حساب مدیر بسازید. ترمینال هنگام استفاده باز بماند. با `Ctrl+C`، Nodemon و سرور وب متوقف می‌شوند.

هر بار بعد فقط `npm run dev` لازم است. Nodemon تغییر فایل‌های `src`، `public` و `.env` را می‌بیند و سرور را دوباره اجرا می‌کند. برای اجرای عادی بدون نظارت تغییر کد، پس از آماده‌بودن دیتابیس از `npm start` استفاده کنید.

## MongoDB محلی پروژه چگونه آماده می‌شود؟

این برنامه برای ثبت چندبخشی اطلاعات از تراکنش استفاده می‌کند؛ MongoDB باید Replica Set باشد. راه‌انداز قبل از Nodemon، از **همان فایل mongod نصب‌شده** یک نمونهٔ محلی تک‌عضوی مخصوص این پروژه آماده می‌کند:

- آدرس پیش‌فرض: `mongodb://127.0.0.1:27018/?replicaSet=rs0`
- پوشهٔ داده: `data/mongodb-local` در همین پروژه.
- گزارش خطا: `data/mongodb-local/mongod.log`.
- دیتابیس: `kunduz_courses`.

پورت ۲۷۰۱۸ از پورت معمول ۲۷۰۱۷ جداست؛ سرویس ویندوز، تنظیمات و دیتابیس‌های فعلی MongoDB شما تغییر نمی‌کنند. اگر نمونهٔ پروژه از قبل آماده باشد، همان دوباره استفاده می‌شود؛ چیزی پاک یا از نو ساخته نمی‌شود. پس از بستن Nodemon، نمونهٔ محلی MongoDB مانند یک سرویس در پس‌زمینه می‌ماند و با اجرای بعدی دوباره استفاده می‌شود. پس از راه‌اندازی مجدد کمپیوتر، `npm run dev` آن را دوباره آماده می‌کند. MongoDB روی loopback اجرا می‌شود.

در ویندوز، `mongod.exe` ابتدا از PATH و سپس از مسیر معمول `C:\Program Files\MongoDB\Server\<version>\bin` پیدا می‌شود. برای نصب سفارشی، این خط را در فایل `.env` اضافه کنید:

```dotenv
MONGOD_PATH="C:\Program Files\MongoDB\Server\8.0\bin\mongod.exe"
```

مسیر را مطابق نسخهٔ نصب‌شدهٔ خود تغییر دهید. اگر از مسیر دارای بک‌اسلش استفاده می‌کنید، مقدار بالا با parseEnv استاندارد Node خوانده می‌شود.

## اگر از قبل فایل .env دارید

راه‌انداز آن را بازنویسی نمی‌کند. برای استفاده از دیتابیس تمرینی مستقل، `MONGODB_URI` را به آدرس پیش‌فرض بالا تغییر دهید. **تغییر آدرس، داده‌های دیتابیس قبلی را منتقل نمی‌کند**؛ اگر در نسخهٔ قبلی اطلاعات ثبت کرده‌اید، اول پشتیبان بگیرید و سپس در دیتابیس جدید بازیابی کنید.

اگر MongoDB فعلی شما از قبل Replica Set است، می‌توانید آدرس همان دیتابیس را در `MONGODB_URI` و نام آن را در `MONGODB_DB` نگه دارید؛ راه‌انداز فقط اتصال را بررسی می‌کند و برای آدرس سفارشی، mongod جدید اجرا نمی‌کند. MongoDB معمولی standalone برای تراکنش‌های این نسخه کافی نیست. فایل `.env` کلید خصوصی دارد؛ آن را منتشر نکنید.

اگر کد اولیه را گم کرده‌اید، مقدار `SETUP_TOKEN` را از `.env` بخوانید؛ فایل را پاک یا کلیدها را برای دیگران ارسال نکنید.

## استفاده از برنامه

ابتدا استاد بسازید، سپس کورس ایجاد کنید و داخل همان کورس ثبت‌نام/Excel، حاضری آنلاین، گزارش و تصدیق‌نامهٔ چاپی/PDF را مدیریت کنید. تاریخ‌های ورودی میلادی و نمایش آن‌ها شمسی است. امکانات نسخهٔ وب تغییر نکرده‌اند؛ این به‌روزرسانی صرفاً راه‌اندازی محلی با Nodemon را آماده می‌کند. نسخهٔ دسکتاپ مستقل و دست‌نخورده است.

پشتیبان دستی و بازیابی از تنظیمات؛ پشتیبان خودکار در `backups` هنگام فعال‌بودن سرور، هر ساعت با نگهداری آخرین ۳۰ نسخه.

آزمون عمومی: `npm test`. آزمون واقعی MongoDB پس از آماده‌شدن نمونهٔ محلی:

```powershell
$env:TEST_MONGO='1'
$env:MONGODB_URI='mongodb://127.0.0.1:27018/?replicaSet=rs0'
npm test
```
