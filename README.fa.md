# همراه محصل — سیستم مدیریت کورس‌های پوهنتون کندوز

دو پروژهٔ مستقل ساخته شده‌اند:

- `web`: Express 5 + Bootstrap 5 + MongoDB؛ برای استفاده از مرورگر.
- `desktop`: Electron 41 + Express + Bootstrap + SQLite؛ برای استفادهٔ آفلاین در ویندوز ۶۴ بیتی.

هیچ‌یک برای اجرا به پوشه یا دیتابیس نسخهٔ دیگر نیاز ندارد. هر نسخه نسخهٔ کامل سورس، فایل قفل وابستگی‌ها، فونت محلی، لوگوها و نمونه‌های ساختگی را دارد. اطلاعات نسخه‌ها خودکار همگام نمی‌شود؛ انتقال اختیاری با پشتیبان JSON از تنظیمات ممکن است.

## انتقال به دسکتاپ شخصی

فایل ZIP را استخراج کنید. روی `Copy-To-Desktop.ps1` راست‌کلیک و Run with PowerShell را انتخاب کنید یا پوشهٔ استخراج‌شده را به دسکتاپ منتقل کنید. اسکریپت پوشهٔ `Hamrah-Mohasel` را روی دسکتاپ واقعی حساب ویندوز می‌سازد. اگر همان نام قبلاً وجود داشته باشد پوشه‌ای با زمان جدید ایجاد می‌کند و فایل‌های قبلی را بازنویسی نمی‌کند.

## نصب نسخهٔ آمادهٔ ویندوز

فایل `Hamrah-Mohasel-Setup-1.0.0.exe` را اجرا کنید. مسیر نصب قابل انتخاب است و میانبر روی دسکتاپ و منوی Start ساخته می‌شود. برای این نسخهٔ آماده Node.js، MongoDB و اینترنت لازم نیست.

در اولین اجرا کد راه‌اندازی در یک پیام نمایش داده می‌شود. آن را در فورم نخستین مدیر وارد کنید؛ نام، نام کاربری و رمز دلخواه با حداقل ۱۰ حرف تعیین نمایید. سپس با همان حساب وارد شوید. رمز پیش‌فرض مشترک وجود ندارد.

اطلاعات برنامه در `%APPDATA%\kunduz-course-desktop` قرار می‌گیرد: `courses.sqlite`، `config.json` و پوشهٔ `backups`. نام پوشه در بعضی بسته‌های Electron ممکن است از نام محصول گرفته شود؛ مسیر قطعی با `app.getPath('userData')` تعیین می‌شود. حذف برنامه اطلاعات کاربری را پاک نمی‌کند. پیش از نصب مجدد یا انتقال دستگاه، از تنظیمات پشتیبان بگیرید.

نصب‌کننده بدون امضای دیجیتال ناشر ساخته می‌شود. ساخت بسته و اجرای Electron در Linux بررسی شده است؛ نصب و اجرای همین فایل exe روی ویندوز در این محیط قابل آزمون نبوده است.

## اجرای سورس نسخهٔ وب

پیش‌نیاز: Node.js 24 یا جدیدتر، npm و MongoDB 8 به شکل Replica Set. فایل Compose برای یک MongoDB محلی آماده است. تراکنش‌ها به Replica Set نیاز دارند؛ MongoDB standalone کافی نیست.

در پوشهٔ `web`:

```sh
npm ci
docker compose up -d --wait
npm run setup
npm start
```

آدرس: `http://127.0.0.1:3000`

`npm run setup` فایل `.env` را با کلیدهای تصادفی می‌سازد و کد راه‌اندازی مدیر را نمایش می‌دهد. آن را در صفحهٔ اولین اجرا وارد کنید. اگر `.env` موجود باشد بازنویسی نمی‌شود؛ کد در `SETUP_TOKEN` همان فایل قرار دارد. در ویندوز `start-web.cmd` همین مراحل را انجام می‌دهد؛ Docker Desktop باید از قبل فعال باشد.

MongoDB در این Compose فقط به loopback دستگاه وصل است. برنامه نیز پیش‌فرض به `127.0.0.1` گوش می‌کند. برای شبکهٔ داخلی، مدیر تخنیکی باید `HOST`، فایروال، TLS و احراز هویت MongoDB را متناسب با محیط تنظیم کند. برای اتصال TLS از `COOKIE_SECURE=1` و در صورت وجود یک reverse proxy قابل اعتماد از `TRUST_PROXY=1` استفاده شود. اجرای مستقیم چند process وب برای این نسخه طراحی نشده است؛ یک process اپلیکیشن اجرا کنید.

برای توقف MongoDB: `docker compose down`؛ داده‌ها در volume باقی می‌مانند. گزینهٔ `-v` داده‌ها را حذف می‌کند.

## اجرای سورس دسکتاپ و ساخت مجدد

در پوشهٔ `desktop`:

```sh
npm ci
npm start
```

اولین نصب وابستگی‌ها اینترنت می‌خواهد؛ پس از آن اجرای روزمره آفلاین است. نسخهٔ دسکتاپ مسیر دیتابیس و کلیدهای امنیتی را خودکار در اطلاعات کاربری ایجاد می‌کند. فایل `.env` نسخهٔ وب را به آن کپی نکنید.

ساخت نصب‌کنندهٔ ویندوز:

```sh
npm run build:win
```

خروجی در `desktop/dist` قرار می‌گیرد. نصب‌کننده با اسکریپت NSIS موجود در `electron/installer.nsi` ساخته می‌شود؛ فایل حذف برنامه نیز دارد. سورس دسکتاپ مستقل است و به مسیر `../web` ارجاع ندارد.

## روش استفاده

۱. ابتدا در «استادان و محصلین» استاد و حساب کاربری او را ثبت کنید. حساب را می‌توان غیرفعال کرد؛ اجازهٔ اصلاح حاضری امروز نیز قابل تعیین است. مدیر می‌تواند مدیر دیگری نیز ایجاد کند؛ آخرین مدیر فعال محافظت می‌شود.

۲. کورس را با کد یکتا، استاد، ظرفیت، جلسات، روزها و زمان آغاز و ختم بسازید.

۳. کورس را باز کنید. ثبت‌نام، حاضری، گزارش و تصدیق‌نامه با تب‌های داخلی همان کورس قابل دسترس است.

۴. محصل را دستی ثبت کنید یا Excel را وارد نمایید. پیش‌نمایش قابل ویرایش است و نتیجهٔ ثبت، خطاها و تکراری‌ها نمایش داده می‌شود. داده‌ها پس از ثبت در دیتابیس ذخیره می‌شوند و به فایل وابسته نمی‌مانند.

۵. تاریخ حاضری را انتخاب و وضعیت تمام محصلین را تعیین کنید. ذخیره دوباره حاضری را اصلاح می‌کند و سطر تکراری ایجاد نمی‌شود. استاد فقط امروز و کورس خود را ثبت می‌کند؛ اصلاح ثبت قبلی نیازمند اجازهٔ مدیر است. مدیر می‌تواند تاریخ گذشته در محدودهٔ دوره را اصلاح کند. تاریخ آینده مجاز نیست.

۶. در تب حاضری «چاپ فورم خالی» دقیقاً سه ستون شماره، اسم و ولد دارد. حاضری دیجیتال علاوه بر این سه مشخصه، انتخاب وضعیت دارد. شماره تماس، دیپارتمنت و سایر مشخصات در فورم حاضری چاپ نمی‌شوند.

۷. گزارش هر کورس دارای فیلتر تاریخ، شمارش حاضر/غیرحاضر/رخصت/ثبت‌نشده و فیصدی است. خروجی Excel حاضری شامل همهٔ تاریخ‌های کورس است؛ عنوان دکمه نیز این موضوع را مشخص می‌کند. جستجوی استاد در فهرست کورس‌ها و انتخاب کورس، گزارش را به استاد و کورس مربوط محدود می‌کند.

۸. پس از تکمیل دوره، وضعیت کورس را «تکمیل‌شده» کنید. پیش‌فرض شرط تصدیق‌نامه کمتر از ۱۰ غیرحاضری است؛ حد در تنظیمات تغییر می‌کند. حداقل یک جلسه و حاضری کامل همهٔ جلسات ثبت‌شده لازم است. رخصت غیرحاضری حساب نمی‌شود؛ فیصدی برابر روزهای حاضر تقسیم بر جلسات ثبت‌شده است. بررسی تکمیل تمام جلسات برنامه‌ریزی‌شده به عهدهٔ مدیر است.

۹. تصدیق‌نامهٔ یک محصل یا همهٔ واجدین شرایط را صادر کنید؛ شمارهٔ یکتا برای هر محصل/کورس ثابت می‌ماند. در صفحهٔ چاپ، چاپگر یا Save as PDF را انتخاب کنید. لوگوها، متن پشتو، عنوان اداره و نام مسئولان از نمونهٔ ارسالی گرفته شده‌اند. قالب HTML چاپی بازطراحی شده است؛ تزئینات و جای‌گذاری آن کپی دقیق صفحهٔ Word نیست. امضاها جای خالی برای امضای واقعی دارند. نام مسئولان در تنظیمات قابل تغییر است.

۱۰. سمینارها و برنامه‌های ویژه در یک بخش با دو تب قرار دارند: ایجاد، ویرایش، جزئیات، حذف با تأیید، جستجو، فیلتر تاریخ/وضعیت/مکان و برای برنامه‌ها نوع، مرتب‌سازی زمانی و چاپ فهرست. این بخش ثبت‌نام اشتراک‌کننده، سوال امتحان یا نمره‌دهی ندارد.

۱۱. از تنظیمات پشتیبان JSON بگیرید. بازیابی تمام اطلاعات قبلی را جایگزین کرده و نشست‌ها را باطل می‌کند؛ سپس با حساب موجود در پشتیبان وارد شوید. نسخهٔ خودکار ۳۰ ثانیه پس از اجرای برنامه و سپس هر ساعت در زمان بازبودن برنامه ساخته می‌شود؛ آخرین ۳۰ نسخه نگهداری می‌گردد. پشتیبان شامل اطلاعات شخصی و hash رمزهاست؛ در محل امن نگهداری شود.

## قالب Excel واقعی

در نمونهٔ شما سطر سوم عنوان‌هاست:

| ستون | مقدار |
|---|---|
| A | شماره |
| B | اسم |
| C | ولد |
| D | دیپارتمنت |
| E | پوهنځی |
| F | سمستر |
| G | ولایت |
| H | شماره تماس |
| I | ملاحظات |

برنامه عنوان‌ها را در ۳۰ سطر اول جستجو می‌کند و محل ستون‌ها را تشخیص می‌دهد؛ ترتیب می‌تواند تغییر کند. اگر عنوان‌ها متفاوت باشند در بخش «تنظیم دستی ستون‌ها» شمارهٔ سطر عنوان و ستون هر فیلد را تعیین کنید؛ A=1 و B=2 و … . پیش‌نمایش اسم و ولد، دیپارتمنت، پوهنځی، سمستر، ولایت و تماس را قابل اصلاح نشان می‌دهد. سطرهای فاقد اسم یا ولد، موارد تکراری و تکمیل ظرفیت جدا گزارش می‌شوند. پشتیبانی از `.xlsx` است؛ فایل `.xls` ابتدا در Excel به `.xlsx` تبدیل شود. حداکثر حجم ۵ مگابایت و حداکثر ۱۰۰۰۰ سطر است.

تشخیص تکراری بر پایهٔ شماره کارت در صورت وجود و سپس اسم/ولد نرمال‌شده با بررسی تماس انجام می‌شود. دو محصل هم‌نام با ولد یکسان باید با شماره کارت و مشخصات دقیق تفکیک شوند؛ موارد حساس پیش از تأیید بررسی شوند. فایل نمونه ۶۸ محصل دارد و در آزمایش واقعی هر ۶۸ سطر بدون خطا وارد شدند. نمونه‌ها خودکار به دیتابیس کاری اضافه نمی‌شوند.

## تاریخ‌ها و امنیت

نمایش تاریخ و اعداد در رابط به فارسی و تقویم هجری شمسی با منطقهٔ زمانی کابل است. کنترل انتخاب تاریخ از نوع استاندارد مرورگر است؛ در حالت ورود متنی مقدار ISO میلادی `YYYY-MM-DD` می‌پذیرد. در دیتابیس تاریخ‌ها به همین قالب ذخیره و بر اساس مقدار واقعی مرتب می‌شوند.

رمزها با bcrypt hash شده‌اند؛ نشست در دیتابیس ذخیره می‌شود، محدودیت ورود و CSRF فعال است و تمام مسیرهای حساس در Backend نقش و مالکیت کورس را بررسی می‌کنند. SQLite دارای WAL، کلید خارجی و شاخص یکتا است. MongoDB دارای collections مستقل، شاخص یکتا و تراکنش است. ویرایش‌های مرتبط و واردکردن Excel در تراکنش انجام می‌شود. حذف کورس دارای محصل و حذف ثبت‌نام دارای حاضری/تصدیق‌نامه محافظت شده‌اند.

## آزمون‌ها

```sh
# در web یا desktop؛ آزمون مستقل SQLite و نمونهٔ واقعی Excel
npm test

# در web با MongoDB Replica Set فعال؛ دیتابیس آزمایشی موقتی
TEST_MONGO=1 npm test
```

آزمون‌ها حساب مدیر/استاد، CSRF، جلوگیری از ثبت تکراری، مالکیت کورس، اجازهٔ اصلاح حاضری، تاریخ آینده، صدور یکتا، حد ۹/۱۰ غیرحاضری، واردکردن فایل واقعی، Excel خروجی، چاپ و بازیابی را بررسی می‌کنند. دیتابیس آزمون از دادهٔ کاری جداست. در PowerShell برای آزمون MongoDB از `$env:TEST_MONGO='1'; npm test` استفاده کنید.

در محیط ساخت، گردش واقعی رابط در Chromium با ورود مدیر، ساخت استاد/کورس، واردکردن ۶۸ محصل، حاضری، گزارش، صدور گروهی و ثبت سمینار بررسی شده و خطای JavaScript مشاهده نشده است. تصاویر پیش‌نمایش و یک PDF نمونه همراه تحویل هستند. بستهٔ ویندوز ساخته می‌شود؛ آزمون نصب نهایی روی ویندوز باید روی دستگاه مقصد انجام شود.
